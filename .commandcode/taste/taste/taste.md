- Values accurate, tidy documentation and copy: expects misleading/incorrect docstrings, inline comments, and UI help text to be corrected and clarified, not just the functional code. Confidence: 0.5
- Cares about user-facing label wording matching the real user intent/context: wants action-oriented labels (e.g. a pending-order button reading "Bayar" on a page of unpaid orders) instead of technical/implementation jargon like "Buka QRIS Statis". When he quotes a piece of UI text ("tulisan ... itu jadi ..."), he means that literal label should be changed — not the flow behind it — so read such terse feedback as copy/text, not behavior. Confidence: 0.55
- Wants setup/deployment instructions delivered as a written, step-by-step guide ("panduan") kept as a repo markdown file, not just chat instructions. Confidence: 0.5
- Thinks print/utility pages (e.g. ONU stickers, print_invoice, print_vouchers, print_payslip) should NOT be standalone sidebar menu entries — they should be reached contextually via a button on the related page (e.g. "Stiker ONU" on the Customers page). Expects deduplication: if a page is already accessible from its natural place and is a standalone print view without sidebar, don't also list it as a menu item. Confidence: 0.6
- Prefers UI to *hide* sections that aren't relevant to the current mode/feature setting, rather than showing them disabled/greyed — e.g. when a feature (like RADIUS) is off, its tabs/cards/related controls should disappear, keeping only the settings needed to re-enable it; when Multi-Router mode is active, the single-router MikroTik host/port/user/password fields are hidden (replaced by a hint pointing to the router menu) "biar gak bingung"; and in single-router mode the Router tab and the per-page router filters (Pelanggan, Paket Internet, Paket Voucher, Stiker ONU) should be hidden entirely ("kalau single router berarti sembunyikan aja tab router"), reappearing only in multi-router mode. Motivation is reducing user confusion about which settings/options actually apply. Confidence: 0.85
- Wants UI copy/labels *consistent* across the whole app for the same state, not just clear in one place: when a button is renamed (e.g. "Buka QRIS Statis" → "Bayar" on unpaid orders), he expects every sibling variant to be unified too (the other gateways' "Lanjutkan Pembayaran" → "Bayar"), and approves that sweep with a one-word "ya". Sweep all views for the old label and report that none remain. Confidence: 0.6
- Prefers feature/domain-specific settings to live inside that feature's own menu/page rather than being lumped on a central Settings page — e.g. RADIUS mode in the RADIUS page, WhatsApp gateway in the WhatsApp page, MikroTik multi-router/default-router/credentials in the MikroTik menu, and AI/Telegram/WhatsApp-bot/Gemini toggles in a dedicated "Asisten AI" menu (`/admin/ai`) instead of buried in Pengaturan ("atau bisa di pindah menunya? biar enak gitu loh terstruktur lebih enak"); the general Settings page should hold only truly global options, with a short link pointing to the moved feature page. He also expects *parity* between similar integrations rather than one-off exceptions: once WhatsApp has its own menu he immediately asks whether Telegram does too ("kalau telegram apa udah menunya?"), so when a pattern is applied to one integration, proactively check every sibling integration and either bring them in line or say plainly which ones still lack it. - Prefers destructive/irreversible actions (e.g. deleting a router) to be guarded rather than silently cascading: block with a clear reason when other records still reference it, offer to reassign/move the affected records first, and require an explicit "force" opt-in — approved this design when proposed.
